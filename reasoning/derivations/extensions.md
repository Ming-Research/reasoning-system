Decision extension-reviews: Is a project's work reviewed against its decisions in the same review as a change to its records?

Chosen: two-reviews, because the owner rules each change to the records (C:extensions-scope), which is reviewed before the owner rules it, while the work's code is mostly written after the owner rules {F:records-before-code: in wf-agents' works a change to the records is designed and put to the owner before the code is written, as in its flow up to 2026-11-01}, so one review would hold the owner's ruling until the code is written, and code would be written on choices not yet ruled (C:owner-inputs); one-review keeps one frame, a fix crossing both seen at once (C:extensions-scope).

Options:
- two-reviews: the review of the records before the cards go to the owner, the review of the work once its code is written
  + over one-review: the owner rules before the code is written
- one-review: one review of the records and the work together, once the work is written
  + over two-reviews: one frame, a fix crossing both seen at once (C:extensions-scope)
